# The ysmood dependency chain and replacement options

- **Date:** 2026-09-05
- **Ticket:** [#10](https://github.com/headlesslab/wand/issues/10) (research, child of wayfinder map [#1](https://github.com/headlesslab/wand/issues/1))
- **Method:** shallow clone of `go-rod/rod@main` (`d38c753`, 2026-08-11) and full clones of the seven `ysmood/*` modules checked out at the versions pinned in rod's `go.mod`; grep-based call-site counts; GitHub REST API via `gh api` for repository metadata, issues and pull requests. Every figure below is from those primary sources; nothing here is a recommendation.

## Question (verbatim from #10)

> For each of upstream's direct dependencies (ysmood/fetchup, goob, got, gotrace, gson, leakless; gop indirect): what does rod use it for, which API surface, how many call sites, the maintainer's activity, and the options: **keep pinned**, **internalize into wand** (MIT), or **replace** with stdlib or a mainstream library.
>
> Note fetchup's v0.2.3 to v0.5.x API break behind upstream issues #1195 / #1203, and how the active forks handled it (runZeroInc/go-rod vendored dependencies; LQR471814/rod removed fetchup and switched to sonic).
>
> Output: a per-dependency table on a `research/` branch. Do not decide.

## Context: rod's whole third-party graph is ysmood

`go.sum` lists exactly seven modules, all under `github.com/ysmood/`; there is no other third-party code in the build ([go.sum](https://github.com/go-rod/rod/blob/main/go.sum), [go.mod](https://github.com/go-rod/rod/blob/main/go.mod)). All seven are MIT-licensed, copyright Yad Smood. Every one of them is itself stdlib-only in non-test code (their `go.mod` files list only each other, and only for tests, except got which requires gop at runtime).

rod itself: 151 non-test Go files / 43,910 lines (30,618 of them the generated `lib/proto`), 35 test files / 12,358 lines (root package 5,346; `lib/proto` 4,742 of which `definitions_test.go` is 4,542 generated lines; the rest of `lib/` 2,270).

## Per-dependency detail

### fetchup v0.2.3

**What rod does with it.** `lib/launcher/browser.go` `Browser.Download()` builds one URL per host (`HostGoogle` = storage.googleapis.com chromium-browser-snapshots, `HostNPM` = registry.npmmirror.com mirror, `HostPlaywright` = playwright.azureedge.net for linux/arm64), then:

```go
fu := fetchup.New(dir, us...)
fu.Ctx = lc.Context
fu.Logger = lc.Logger
if lc.HTTPClient != nil { fu.HttpClient = lc.HTTPClient }
err := fu.Fetch()
...
return fetchup.StripFirstDir(dir)
```

fetchup races the hosts by fetching the first TCP packet from each (`FastestURL`), downloads from the winner with progress logging, detects zip/tar, extracts to `To`, and `StripFirstDir` flattens the single top-level directory. That is the whole surface: two package symbols, three exported struct fields, one method. No test file imports it. ([browser.go](https://github.com/go-rod/rod/blob/main/lib/launcher/browser.go), [fetchup.go @v0.2.3](https://github.com/ysmood/fetchup/blob/v0.2.3/fetchup.go), [utils.go @v0.2.3](https://github.com/ysmood/fetchup/blob/v0.2.3/utils.go))

**Repository.** Created 2023-04-01; 24 tags; v0.2.3 tagged 2023-05-07; latest v0.5.3 published 2025-09-30, which is also the last commit; 0 open issues, 0 open PRs; 4 stars, 2 forks; MIT. At v0.2.3: 4 non-test files / 548 lines, 2 test files / 299 lines, `go 1.20`, non-test imports are stdlib only (got is a test dependency). At v0.5.3: 7 non-test files / 956 lines after adding `pkg/` (golangci-lint and golang-migrate installers unrelated to rod). ([repo](https://github.com/ysmood/fetchup), [tags](https://github.com/ysmood/fetchup/tags), [releases](https://github.com/ysmood/fetchup/releases))

**Keep-pinned facts.** (1) `go.mod` pins v0.2.3, but downstream `go get -u` or renovate-style bumps select v0.4.0+ and the build fails; this is the single most-upvoted problem in the upstream tracker (see next section). (2) v0.2.3's `UnZip` comments "Because zip format does not streaming, we need to read the whole file into memory" and buffers the entire archive; v0.3.0 (2025-03-09) merged PR #2 "Use a temp file when downloading zip to avoid big RAM usage". v0.3.0 is the last version whose `New` signature matches rod's call, and it is the version people in #1195/#1203 report pinning to. ([download.go @v0.2.3](https://github.com/ysmood/fetchup/blob/v0.2.3/download.go), [PR #2](https://github.com/ysmood/fetchup/pull/2), [v0.3.0 release](https://github.com/ysmood/fetchup/releases/tag/v0.3.0))

**Internalize facts.** 548 lines of stdlib-only Go plus one MIT notice. The rod call site would not change.

**Replace facts.** fetchup has no third-party dependencies, so any replacement is a reimplementation of: N-way TCP race, HTTP download with progress, zip/tar-gz extraction with path normalisation, top-dir strip. runZero did exactly that (`archive/zip`, `net/http`, `encoding/json`, `gofrs/flock`, ~1,186-line `browser.go` that also resolves Chrome-for-Testing URLs). General-purpose libraries exist but are far larger than the need: hashicorp/go-getter v1.8.9 (MPL-2.0, not MIT-compatible in the same way), mholt/archives v0.1.5 (MIT). ([runZero browser.go](https://github.com/runZeroInc/go-rod/blob/main/lib/launcher/browser.go), [go-getter](https://github.com/hashicorp/go-getter), [archives](https://github.com/mholt/archives))

### The fetchup v0.2.3 -> v0.5.x break and how forks handled it

**The break.** Tag dates: v0.2.3 2023-05-07, v0.2.4 2023-12-07, v0.3.0 2025-03-09, v0.4.0 2025-06-09, v0.5.0/1/2 2025-06-11, v0.5.3 2025-09-30. Commit `6b150f4` "simplify the interface" (2025-06-09, released as v0.4.0) changed:

| v0.2.3 / v0.3.0                              | v0.4.0+                                                        |
| -------------------------------------------- | -------------------------------------------------------------- |
| `func New(to string, us ...string) *Fetchup` | `func New(us ...string) *Fetchup`                              |
| field `To string`                            | field `SaveTo string`, default `os.TempDir()/fetchup/<random>` |
| (none)                                       | `func (fu *Fetchup) WithSaveTo(to string) *Fetchup`            |

v0.5.0 (2025-06-11) added `WithContext(ctx)` and `WithLogger(logger)`. All three `With*` methods copy the receiver (`n := *fu; n.X = ...; return &n`) and return the copy; they do not mutate `fu`. Everything else rod touches (`Ctx`, `Logger`, `HttpClient`, `Fetch`, `StripFirstDir`) is unchanged across v0.2.3..v0.5.3. ([compare v0.2.3...v0.5.3](https://github.com/ysmood/fetchup/compare/v0.2.3...v0.5.3), [commit 6b150f4](https://github.com/ysmood/fetchup/commit/6b150f4))

**Upstream symptoms.** rod #1195 "Fail build with new version github.com/ysmood/fetchup v0.4.0" (2025-06-09, 8 comments, 8 thumbs-up) and #1203 (2025-07-01, 7 comments, 13 thumbs-up, the most-upvoted open issue) both show `browser.go:138:25: too many arguments in call to fetchup.New have (string, []string...) want (...string)`. Comments recommend `go get github.com/ysmood/fetchup@v0.2.3` or `replace github.com/ysmood/fetchup => github.com/ysmood/fetchup v0.3.0`. ([#1195](https://github.com/go-rod/rod/issues/1195), [#1203](https://github.com/go-rod/rod/issues/1203))

**Three mutually exclusive open PRs** rewrite the same hunk of `lib/launcher/browser.go` (the `Download()` call site at line 138); each is `MERGEABLE` against `main` on its own and none has been merged; per the harvest-list research in wand #7, only #1241 has ever run upstream CI, so none of the three has CI results:

The `#1231` defect follows from fetchup's `With*` implementation (`n := *fu; n.SaveTo = to; return &n`): the archive is extracted to fetchup's default temp directory while rod looks for the binary under `lc.Dir()` (for example `%AppData%\rod\browser\chromium-1321438` on Windows). rod #1202 (2025-07-01, "panic: open C:\Users\Administrator\AppData\Roaming\rod\browser\chromium-1321438: The system cannot find the file specified", logged right after a successful npmmirror download) shows that same missing-directory symptom; note, however, that #1202 predates #1231 by nine months and was reported against a build that compiled, which with rod's unmodified call site requires fetchup <= v0.3.0, so #1202's own root cause is not established by this analysis. **runZeroInc/go-rod** (module `github.com/runZeroInc/go-rod`, `go 1.26`, 125 commits ahead of upstream, pushed 2026-07-23, 13 stars). It does **not** use a `vendor/` directory; the README's "Inline and vendoring of the ysmood's other packages" means copying goob, gop, got and gson into `pkg/{goob,gop,got,gson}` with each upstream `LICENSE` file kept alongside. fetchup, leakless and gotrace are gone: no import of any `github.com/ysmood/*` path remains. Its `go.mod` instead requires `gobwas/ws`, `gofrs/flock`, `mitchellh/go-ps`, `sirupsen/logrus`, `golang.org/x/sys`. Browser download is a bespoke implementation against the Chrome-for-Testing `last-known-good-versions-with-downloads.json` endpoint with a Puppeteer fallback for linux/arm64. Tests still use the inlined got (61 test files). ([README](https://github.com/runZeroInc/go-rod/blob/main/README.md), [go.mod](https://github.com/runZeroInc/go-rod/blob/main/go.mod), [pkg/](https://github.com/runZeroInc/go-rod/tree/main/pkg))

**LQR471814/rod** (4 commits ahead, pushed 2026-06-01, 0 stars, "fork for use in the ax-distiller project with performance enhancements"). ([commit c2bb4b9](https://github.com/LQR471814/rod/commit/c2bb4b9), [commit 5022a44](https://github.com/LQR471814/rod/commit/5022a44), [go.mod](https://github.com/LQR471814/rod/blob/main/go.mod))

**PrismAIO/rod** (8 commits ahead, pushed 2026-06-15, 2 stars). Commit `701b4f6` "update fetchup" (2025-07-27) bumps fetchup v0.2.3 -> v0.5.2 and got v0.40.0 -> v0.41.0 and rewrites the call site as four statements: `fu := fetchup.New(us...)`, `fu.WithSaveTo(dir)`, `fu.WithContext(lc.Context)`, `fu.WithLogger(lc.Logger)`. Because the `With*` methods return a modified copy and these return values are discarded, `fu` keeps fetchup's defaults (temp-dir `SaveTo`, background context, stderr logger) as written; upstream PR #1201 assigns the `WithSaveTo` result and sets `Ctx`/`Logger` as fields. ([commit 701b4f6](https://github.com/PrismAIO/rod/commit/701b4f6), [fetchup.go @v0.5.3](https://github.com/ysmood/fetchup/blob/v0.5.3/fetchup.go))

### goob v0.4.0

**What rod does with it.** `Browser` and `Page` each hold an `event *goob.Observable`. `initEvents` creates it with `goob.New(ctx)` and a goroutine `Publish`es every CDP message into it; `Browser.Event()` / `Page.Event()` call `Subscribe(ctx)` and forward to a fresh channel. Total: `goob.New` x2, `*goob.Observable` x2, `.Subscribe` x2, `.Publish` x2 in `browser.go` and `page.go`; zero test references. goob's purpose per its README: "Go channel doesn't support unlimited buffer size ... unlimited buffer size, one publisher to multiple subscribers, thread-safe, subscribers never block each other, stable event order". ([browser.go](https://github.com/go-rod/rod/blob/main/browser.go), [page.go](https://github.com/go-rod/rod/blob/main/page.go), [goob README](https://github.com/ysmood/goob))

**Repository.** MIT; 63 stars; v0.4.0 tagged 2022-04-09 and no commit since (0 commits between tag and HEAD); 0 open issues or PRs. 2 non-test files / 130 lines (`goob.go`, `pipe.go`), 3 test files / 387 lines; non-test code is stdlib-only, gotrace is a test-only dependency. Exported API: `Observable` (`New`, `Publish`, `Subscribe`, `Len`), `Event`, `Events`, `NewPipe`. ([repo](https://github.com/ysmood/goob), [tags](https://github.com/ysmood/goob/tags))

**Options facts.** Keep: frozen but dependency-free and tiny. Internalize: 130 lines + MIT notice; runZero's `pkg/goob` is exactly this (130 non-test lines). Replace: no widely used Go library provides an unbounded ordered fan-out; a stdlib rewrite would reproduce `pipe.go`'s slice-backed buffer.

### got v0.40.0

got plays two unrelated roles in rod, and the three options mean different things for each.

**Role (a): runtime dependency via `got/lib/lcs`.** `page.go` (root package, non-test) imports `github.com/ysmood/got/lib/lcs` and uses it at lines 806-808 inside `Page.WaitDOMStable`: `xs := lcs.NewWords(domSnapshot.Strings); ys := lcs.NewWords(currentDomSnapshot.Strings); lcs := xs.YadLCS(p.ctx, ys)`, then `df := 1 - float64(len(lcs))/float64(len(ys))` is compared against the caller's `diff` threshold. Surface: two symbols (`NewWords`, `Sequence.YadLCS`), three calls, one file; it is the only non-test reference to got in rod, and it means the whole got module is linked into every rod binary. `lib/lcs` at v0.40.0 is 354 lines (`lcs.go` 157, `sequence.go` 133, `utils.go` 64), stdlib-only. **got v0.43.0 removed `lib/lcs`** (commit `1841850` "replace lcs with histogram diff", 2026-04-23): `git ls-tree <tag> lib/` lists `lcs` for v0.41.0, v0.42.0 and v0.42.4 and not for v0.43.0, so v0.42.4 (requires gop v0.3.2) is the highest got that rod's `page.go` compiles against. rod #1237 (2026-05-31, Debian packager) reports exactly this and asks upstream to move to v0.43.0 "or somehow resolve the use of obsolete APIs"; it has no maintainer response. For this role, "replace" means substituting any LCS or diff-ratio routine over `[]string` (got itself moved to a histogram diff), independent of what the test suite uses. ([page.go L806-808](https://github.com/go-rod/rod/blob/main/page.go), [lib/lcs @v0.40.0](https://github.com/ysmood/got/tree/v0.40.0/lib/lcs), [commit 1841850](https://github.com/ysmood/got/commit/1841850e2725ada03144eaafa24359c3c89dbf37), [got go.mod @v0.42.4](https://github.com/ysmood/got/blob/v0.42.4/go.mod), [rod #1237](https://github.com/go-rod/rod/issues/1237))

**Role (b): test framework.** Everything below this line is test-only code; for this role, "replace" means rewriting assertions and helpers, and "keep pinned" has no version ceiling.

**How it works.** leakless README: "Run sub-process and make sure to kill it when the parent process exits. ## Cross-cutting facts

- **Public API coupling.** Of the seven modules, only gson leaks into rod's exported API (10 signatures, 27 protocol fields). goob, leakless and fetchup are behind rod's own types; got's `lib/lcs` is internal to `page.go`; gotrace and gop never touch non-test, non-example code.
- **Frozen vs. active.** goob (2022-04), gotrace (2022-04) and gson (2022-11) have had no commits since their pinned tags. leakless last moved 2024-07. fetchup (2025-09), got (2026-06) and gop (2026-04) are active, and the two active ones that rod pins (fetchup, got) are exactly the two whose newer versions break rod (`New` signature at fetchup v0.4.0, #1195/#1203; `lib/lcs` removal at got v0.43.0, #1237).
- **Fork precedent.** runZero is the only fork that eliminated the ysmood module graph, by inlining 4 modules (~4,450 lines) and dropping 3 (fetchup, leakless, gotrace) in favour of ~2,000 lines of its own launcher code plus five new third-party modules. PrismAIO and the three open upstream dependency PRs (#1201, #1231, #1236) keep the graph and bump versions; two of the four (PrismAIO, #1231) discard the `WithSaveTo` return value. LQR removes browser downloading rather than replacing it.
- **Licensing.** All seven modules are MIT (copyright Yad Smood, 2019-2023). runZero's inlining pattern keeps each upstream `LICENSE` file next to the copied package.
