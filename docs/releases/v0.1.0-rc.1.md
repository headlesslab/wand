**wand is a Chrome DevTools Protocol driver for browser automation and web scraping in Go.** Its code is a snapshot of [go-rod](https://github.com/go-rod/rod) at commit `393ac0d` (2024-12-07), renamed to `github.com/headlesslab/wand` and maintained independently by headlesslab; upstream's MIT licence and the attribution in [`NOTICE`](https://github.com/headlesslab/wand/blob/main/NOTICE) are kept as they are. Thank you to ysmood and to everyone who wrote go-rod — this release is that work brought current, and the pull requests harvested from its tracker are credited in the notes below.

**Moving a go-rod program over is five changes**, each one the compiler or the flag parser points at: the import prefix (`github.com/go-rod/rod` → `github.com/headlesslab/wand`, `rod.` → `wand.`); `github.com/ysmood/gson` → `github.com/headlesslab/lazyjson`, identifier for identifier; the dev-only symbols that left the public API (`lib/assets`, seven `lib/utils` helpers, the launcher's revision and host constants, `defaults.LockPort`); the commands (`lib/launcher/rod-manager` → `cmd/wand-manager`, with the new `cmd/wand-fetch-browser` beside it); and the flag (`-rod=` → `-wand=`, `DISABLE_ROD_FLAG` → `DISABLE_WAND_FLAG`). [The migration guide](https://github.com/headlesslab/wand/blob/main/docs/migrating-from-go-rod.md) has each with the `sed` line that does it, and a Known limitations section for what this release does not fix. Everything else keeps its name and its behaviour — in practice, not as a promise ([ADR-0002](https://github.com/headlesslab/wand/blob/main/docs/adr/0002-no-api-compatibility-with-go-rod.md)).

**Four things behave differently and no compiler will tell you.** `launcher.NewUserMode()` drives a persistent profile wand owns (`os.UserConfigDir()/wand/user-mode`) instead of Chrome's own, which branded Chrome has refused remote debugging on since Chrome 136 — so User mode works again, and your sign-ins do not come with it. The browser cache moved to `os.UserCacheDir()/wand/browser`, and a System browser you already have is launched before anything is downloaded. leakless is gone: the Orphan guard keeps the same guarantee out of the operating system and a pipe wand never speaks on, writing no binary and starting no process, while `Launcher.Leakless()` is unchanged. And `cdp.ErrCtxDestroyed` matches the second message Chrome 152 introduced, so `errors.Is` keeps working across the whole Support window.

**What is tested, and what is not.** Every pull request and every push to `main` runs the whole suite with `-race` against Chrome 153.0.8010.12 on linux/amd64, linux/arm64, windows/amd64 and darwin/arm64 — Tier 1 — the two Linux ones on the Go floor of 1.21 as well as on Go stable, and every run ends by proving that no browser process and no profile directory were left behind. The Support window is Chrome 150 to 153: the Target Chrome is the tested one, the three milestones before it are best-effort, and the oldest of them runs nightly, gating nothing. Tier 2 — darwin/amd64, windows/arm64 and linux/loong64 — is built and vetted in CI and never tested with a browser. A browser of another major version is launched anyway, with one line through the browser's logger naming both.

**The container image** is `ghcr.io/headlesslab/wand`, tagged with this release: `ubuntu:noble` with that same Chrome inside it, hash-verified at build time, and `wand-manager` as its command, in one manifest covering `linux/amd64` and `linux/arm64`.

**Trust it the way you would any binary you did not build yourself**: the [OpenSSF Scorecard](https://scorecard.dev/viewer/?uri=github.com/headlesslab/wand) is published for the repository, every published manifest carries a build-provenance attestation and an SPDX bill of materials in Sigstore's public log — `gh attestation verify oci://ghcr.io/headlesslab/wand:<tag> -R headlesslab/wand` — tags are immutable and are never moved or deleted, and [wand's security policy](https://github.com/headlesslab/wand/security/policy) says where a vulnerability report goes.

**Roadmap**: API modernization and Stealth are planned, with no dates and no ordering promise. The awkward part said plainly — **the API modernization will change wand's API in a later minor.** Until 1.0 a minor may break and a patch never does, so `go get -u=patch` is the safe upgrade, and an exported symbol carries a `// Deprecated:` marker naming its replacement for at least one minor before it goes ([ADR-0008](https://github.com/headlesslab/wand/blob/main/docs/adr/0008-fresh-v0-series-one-milestone-release-per-chrome-stable.md)). wand ships no evasion code, and go-rod/stealth does not build against it.

**A candidate first, then the release.** `v0.1.0` carries the last candidate's code unchanged, tagged once at least 14 days have passed since rc.1, at least 7 since the latest candidate, and no issue labelled `release-blocking` is open; any change at all makes rc.N+1. Tell us what breaks: the [release candidate feedback issue](https://github.com/headlesslab/wand/issues/117) is open for the whole soak, and [a new issue](https://github.com/headlesslab/wand/issues/new) is welcome at any time. A report naming the Chrome version, the platform and what go-rod did instead is the useful kind.

**wand 是 Go 语言的 Chrome DevTools Protocol 驱动，用于浏览器自动化与网页抓取。** 它的代码取自 [go-rod](https://github.com/go-rod/rod) 提交 `393ac0d`（2024-12-07）的一份快照，重命名为 `github.com/headlesslab/wand`，由 headlesslab 独立维护；上游的 MIT 许可与 [`NOTICE`](https://github.com/headlesslab/wand/blob/main/NOTICE) 中的署名原样保留。感谢 ysmood 以及每一位写过 go-rod 的人——这个版本就是那份工作被带到当下，从 go-rod 问题区收割进来的 PR 在下方的发布说明里逐条署名。

**把 go-rod 程序迁过来是五处改动**，每一处编译器或参数解析都会直接指给你：导入前缀（`github.com/go-rod/rod` → `github.com/headlesslab/wand`，`rod.` → `wand.`）；`github.com/ysmood/gson` → `github.com/headlesslab/lazyjson`，标识符逐一对应；离开公开 API 的开发期符号（`lib/assets`、`lib/utils` 的七个辅助函数、launcher 的 revision 与 host 常量、`defaults.LockPort`）；两个命令（`lib/launcher/rod-manager` → `cmd/wand-manager`，旁边新增 `cmd/wand-fetch-browser`）；以及那个 flag（`-rod=` → `-wand=`，`DISABLE_ROD_FLAG` → `DISABLE_WAND_FLAG`）。[迁移指南](https://github.com/headlesslab/wand/blob/main/docs/migrating-from-go-rod.md)（英文）逐条给出，并附上能直接执行的 `sed` 命令，还有一节「已知限制」写明这个版本不修什么。除此之外，名字与行为都还是原来的样子——这是事实，不是承诺（[ADR-0002](https://github.com/headlesslab/wand/blob/main/docs/adr/0002-no-api-compatibility-with-go-rod.md)）。

**有四处行为变了，而且编译器不会提醒你。** `launcher.NewUserMode()` 现在使用 wand 自己的持久化配置目录（`os.UserConfigDir()/wand/user-mode`），而不是 Chrome 自带的那个——自 Chrome 136 起，带品牌的 Chrome 会拒绝在后者上开启远程调试——所以 User mode 又能用了，代价是你原有的登录态不会跟过来。浏览器缓存目录改为 `os.UserCacheDir()/wand/browser`，并且在下载任何东西之前，会先启动你已经装好的 System browser。leakless 没有了：Orphan guard 靠操作系统本身，以及一条 wand 只开不说话的管道，提供同样的保证，不落地任何二进制、不起任何进程，而 `Launcher.Leakless()` 一切照旧。另外 `cdp.ErrCtxDestroyed` 现在也匹配 Chrome 152 新增的那条消息，因此 `errors.Is` 在整个支持窗口内都继续有效。

**什么被测过，什么没有。** 每个 PR、以及每次推送到 `main`，都会在 linux/amd64、linux/arm64、windows/amd64 与 darwin/arm64（即 Tier 1）上，用真实的 Chrome 153.0.8010.12 带 `-race` 跑完整套件，其中两个 Linux 平台除 Go stable 外还跑一遍 Go 下限 1.21，且每次运行结束都会验证没有残留的浏览器进程与配置目录。支持窗口是 Chrome 150 至 153：Target Chrome 是被测的那一个，它之前的三个里程碑属尽力而为，其中最老的那个每晚跑一遍，且不阻塞任何东西。Tier 2——darwin/amd64、windows/arm64 与 linux/loong64——只在 CI 上构建与 vet，从不用浏览器跑。主版本号不同的浏览器照样启动，只在浏览器的 logger 上打一行，写明两个版本号。

**容器镜像**是 `ghcr.io/headlesslab/wand`，随本次发布打标签：`ubuntu:noble`，内含同一个 Chrome（构建时经哈希校验），默认命令是 `wand-manager`，`linux/amd64` 与 `linux/arm64` 在同一个 manifest 里。

**像对待任何一个不是你自己构建的二进制那样去信任它**：仓库发布了 [OpenSSF Scorecard](https://scorecard.dev/viewer/?uri=github.com/headlesslab/wand)；每一个发布出去的 manifest 都在 Sigstore 的公开日志里带有构建来源证明与 SPDX 物料清单——`gh attestation verify oci://ghcr.io/headlesslab/wand:<tag> -R headlesslab/wand`；标签不可变，永不移动、永不删除；漏洞报告该走哪条路，见 [wand 的安全策略](https://github.com/headlesslab/wand/security/policy)。

**路线图**：API modernization 与 Stealth 都在计划中，没有时间表，也不承诺先后。把不好听的话直说——**API modernization 会在之后某个 minor 版本改动 wand 的 API。** 1.0 之前的规则是：minor 可以破坏兼容，patch 永远不会，所以 `go get -u=patch` 是安全的升级方式；导出符号在移除前，至少会带着写明替代者的 `// Deprecated:` 标记经过一个 minor（[ADR-0008](https://github.com/headlesslab/wand/blob/main/docs/adr/0008-fresh-v0-series-one-milestone-release-per-chrome-stable.md)）。wand 不含任何反检测代码，go-rod/stealth 也不能对着 wand 编译。

**先候选，后正式。** `v0.1.0` 原样沿用最后一个候选版本的代码，打标签的条件是：距 rc.1 已过至少 14 天、距最新的候选版本已过至少 7 天，且没有标着 `release-blocking` 的 issue 还开着；期间任何改动都会产生 rc.N+1。有问题请告诉我们：[候选版本反馈 issue](https://github.com/headlesslab/wand/issues/117) 在整个观察期内都开着，也欢迎随时[新开一个 issue](https://github.com/headlesslab/wand/issues/new)。写清 Chrome 版本、平台，以及同样的代码在 go-rod 上是什么表现，是最有用的那种报告。
