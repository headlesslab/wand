wand is a browser automation library for Go. It drives Chrome over the DevTools Protocol and needs no driver binary.

The code began as a snapshot of [go-rod](https://github.com/go-rod/rod) at commit `393ac0d` (2024-12-07), renamed to `github.com/headlesslab/wand` and maintained independently by headlesslab. Upstream's MIT licence and the attribution in [`NOTICE`](https://github.com/headlesslab/wand/blob/main/NOTICE) are kept as they are. Thanks to ysmood and to everyone who contributed to go-rod.

This is wand's first release, published as a release candidate. No API was redesigned. The work went into three things: a dependency graph that upgrades cleanly, correct behaviour on current Chrome, and CI that proves both on every platform wand claims.

## What this release fixes

Six problems a go-rod user runs into today:

- **`go get -u` breaks the build.** Two upstream dependencies changed their APIs and the fixes were never merged (rod #1203, #1195, #1202, #1237). wand's runtime graph is five modules headlesslab maintains — `eventbus`, `lazyjson`, `seqdiff`, `leakcheck`, `fetch` — plus `golang.org/x/sys`, and no test framework is linked into your binary.
- **`launcher.NewUserMode()` fails on every Chrome since 136** (rod #1189, #1184). Branded Chrome refuses remote debugging on its default profile, which is where the preset pointed.
- **linux/arm64 cannot obtain a browser at all.** The archive URL it fell back to stopped resolving. Downloads are pinned to Chrome for Testing now and verified against a recorded SHA-256, served by Google's buckets or npmmirror, whichever answers first.
- **The guard binary trips antivirus** (rod #865, #1214, #1232, #720, #1229). leakless dropped a prebuilt executable into the temp directory; Windows Defender, 360 and Tencent PC Manager flagged it, Falco alerted on it in Kubernetes, and its port lock could hang. Nothing is written to disk now.
- **`errors.Is(err, cdp.ErrCtxDestroyed)` stops matching on Chrome 152**, which changed the message an evaluation interrupted by navigation returns. Both messages match.
- **A browser-closed connection surfaces differently per OS.** It is `io.EOF` everywhere, Windows included.

On top of those, fourteen fixes were harvested from go-rod's unmerged pull requests and its issue tracker. Each has a regression test that fails on the snapshot and passes here:

- **Page and element** — `WaitRepaint` evaluating under the page context (rod #1241), a closed page clearing its session states (rod #1235), element screenshots cropped by the device pixel ratio (rod #1200), `WaitLoad` without the load event object (rod #1150), `WaitEnabled` and `WaitWritable` reading their own attribute (rod #1182).
- **CDP** — control frames kept out of the JSON decoder (rod #1187), a real `Sec-WebSocket-Key` per handshake (rod #1228).
- **Launcher and input** — attaching to a browser already running (rod #1221), `ResolveURL` accepting only a browser's answer (rod #1176), FreeBSD in the discovery tables (rod #1233, #828), a multi-byte character counted as one key (rod #1220).
- **Hijack and pool** — request patterns parsed the way the browser parses them (rod #983), `LoadResponse` bodies that can be sent again (rod #1128), `Pool.Get` after `Cleanup` (rod #1117).

## What is new

- **Browser resolution.** `Launch` takes the first browser it finds and downloads one only when it finds none: `Launcher.Bin()`, then `-wand=bin=`, then `WAND_BROWSER_BIN`, then Chrome, Chromium or Edge installed on the machine, then the browser already in wand's cache, then a download. A developer machine with Chrome on it downloads nothing.
- **Six `WAND_BROWSER_*` variables** — `BIN`, `CACHE`, `HOSTS`, `DOWNLOAD`, `SOURCE`, `BINARY` — for deployments where changing the code is not an option. go-rod had none.
- **`cmd/wand-fetch-browser`** downloads the browser ahead of time and prints its path, for a Docker build or an offline bundle.
- **Pinned browser and protocol.** Target Chrome 153.0.8010.12, protocol r1680125, Companion Chromium 1680292, with every archive hash recorded. They move together once per Chrome stable milestone, through an automated Roll, and [`versions.json`](https://github.com/headlesslab/wand/blob/main/versions.json) records which release carried which pins.
- **Build paths for Domestic platforms**, documented in the README: openEuler 24.03 LTS builds with its own packaged Go; distributions below the Go floor of 1.21 cross-compile or take a tarball from golang.google.cn; `linux/loong64` means new-world (ABI 2.0) only.

## What changed in behaviour

Four things behave differently and no compiler will point at them.

1. **User mode has a profile directory of its own.** `NewUserMode()` uses `os.UserConfigDir()/wand/user-mode`. Your existing Chrome sign-ins do not carry over: sign in once there and the session persists.
2. **The browser cache moved** to `os.UserCacheDir()/wand/browser`, and a browser already installed is used before anything is downloaded. The old `rod/browser` directory is neither read nor deleted; remove it by hand when you are done with go-rod.
3. **`Launcher.Leakless()` switches the Orphan guard.** Same name, same place, same defaults, same guarantee — a browser `Launch()` started does not outlive your process — but it is kept by the operating system and a pipe wand never speaks on, rather than by a helper process.
4. **`cdp.ErrCtxDestroyed` matches two messages.** Comparing `err.Message` yourself is what breaks; use `errors.Is`.

## Migrating from go-rod

Five changes, each one the compiler or the flag parser points at:

| What             | From                                                                                                     | To                                                                  |
| ---------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| import prefix    | `github.com/go-rod/rod`, `rod.`                                                                          | `github.com/headlesslab/wand`, `wand.`                              |
| JSON helper      | `github.com/ysmood/gson`                                                                                 | `github.com/headlesslab/lazyjson`, identifier for identifier        |
| dev-only symbols | `lib/assets`, seven `lib/utils` helpers, the launcher's revision and host constants, `defaults.LockPort` | moved under `internal/`, or into `lib/launcher/pins`                |
| commands         | `lib/launcher/rod-manager`                                                                               | `cmd/wand-manager`, with the new `cmd/wand-fetch-browser` beside it |
| flag             | `-rod=`, `DISABLE_ROD_FLAG`                                                                              | `-wand=`, `DISABLE_WAND_FLAG`                                       |

[The migration guide](https://github.com/headlesslab/wand/blob/main/docs/migrating-from-go-rod.md) gives each one with the `sed` line that does it, and a Known limitations section for what this release does not fix. Everything else keeps its name and its behaviour — in practice, not as a promise: wand offers no API compatibility contract with go-rod ([ADR-0002](https://github.com/headlesslab/wand/blob/main/docs/adr/0002-no-api-compatibility-with-go-rod.md)).

## What is tested

Every pull request and every push to `main` runs the whole suite with `-race` against Chrome 153.0.8010.12 on four platforms, the two Linux ones on the Go floor of 1.21 as well as on Go stable. Each run ends by checking that no browser process and no profile directory were left behind.

- **Tier 1** — linux/amd64, linux/arm64, windows/amd64, darwin/arm64: tested in CI with a real browser.
- **Tier 2** — darwin/amd64, windows/arm64, linux/loong64: built and vetted, never tested with a browser.
- **Support window** — Chrome 150 to 153. The Target Chrome is the tested one; the three milestones before it are best-effort, and the oldest of them runs nightly without gating anything.

Nothing is enforced at runtime: a browser of another major version is launched anyway, with one line through the browser's logger naming both.

## The container image

`ghcr.io/headlesslab/wand`, tagged with this release: `ubuntu:noble` with that same Chrome inside it, hash-verified at build time, `wand-manager` as its command, one manifest covering `linux/amd64` and `linux/arm64`.

## Verifying what you install

Every published manifest carries a build-provenance attestation and an SPDX bill of materials in Sigstore's public log:

```sh
gh attestation verify oci://ghcr.io/headlesslab/wand:<tag> -R headlesslab/wand
```

Tags are immutable and are never moved or deleted. The repository publishes an [OpenSSF Scorecard](https://scorecard.dev/viewer/?uri=github.com/headlesslab/wand), and [the security policy](https://github.com/headlesslab/wand/security/policy) says where a vulnerability report goes.

## Roadmap

API modernization and Stealth are planned. No dates, and no promise about the order.

One thing to weigh before you adopt this: **the API modernization will change wand's API in a later minor.** Until 1.0 a minor may break and a patch never does, so `go get -u=patch` is the safe upgrade, and an exported symbol carries a `// Deprecated:` marker naming its replacement for at least one minor before it goes ([ADR-0008](https://github.com/headlesslab/wand/blob/main/docs/adr/0008-fresh-v0-series-one-milestone-release-per-chrome-stable.md)). wand ships no evasion code, and go-rod/stealth does not build against it.

## About this candidate

`v0.1.0` carries the last candidate's code unchanged. It is tagged once at least 14 days have passed since rc.1, at least 7 since the latest candidate, and no issue labelled `release-blocking` is open. Any change makes rc.N+1 instead.

wand 是一个 Go 的浏览器自动化库，通过 DevTools Protocol 驱动 Chrome，不需要任何 driver 程序。

代码来自 [go-rod](https://github.com/go-rod/rod) 在 `393ac0d`（2024-12-07）这个提交的一份快照，重命名为 `github.com/headlesslab/wand`，由 headlesslab 独立维护。上游的 MIT 许可和 [`NOTICE`](https://github.com/headlesslab/wand/blob/main/NOTICE) 里的署名都原样保留。感谢 ysmood，以及所有给 go-rod 写过代码的人。

这是 wand 的第一个版本，先以候选版本发布。API 没有做任何重新设计，这一版的工作集中在三件事：依赖链能正常升级、在当前 Chrome 上行为正确、并在所有声称支持的平台上用 CI 把前两条验证一遍。

## 修复了哪些问题

下面六个是今天用 go-rod 就会撞上的：

- **`go get -u` 会导致编译失败。** 上游有两个依赖改了 API，修复的 PR 一直没合（rod #1203、#1195、#1202、#1237）。wand 运行时只依赖 headlesslab 维护的五个模块（`eventbus`、`lazyjson`、`seqdiff`、`leakcheck`、`fetch`）和 `golang.org/x/sys`，测试框架也不会再被链进你的二进制。
- **`launcher.NewUserMode()` 从 Chrome 136 起就是坏的**（rod #1189、#1184）。带品牌的 Chrome 不允许在默认用户目录上开远程调试，而这个预设指的正是那个目录。
- **linux/arm64 压根下载不到浏览器。** 它兜底用的那个归档地址早就失效了。现在下载固定到 Chrome for Testing，按记录在案的 SHA-256 校验，Google 的 bucket 和 npmmirror 谁先响应就用谁。
- **守护进程的二进制会被杀毒软件拦下来**（rod #865、#1214、#1232、#720、#1229）。leakless 会往临时目录丢一个预编译的可执行文件，Windows Defender、360、腾讯电脑管家都报过毒，Kubernetes 里 Falco 也会告警，它那个端口锁还可能一直挂住。现在不往磁盘写任何东西。
- **Chrome 152 之后 `errors.Is(err, cdp.ErrCtxDestroyed)` 匹配不上了。** Chrome 改了「求值被导航打断」时返回的错误文案，现在两种文案都能匹配。
- **浏览器关闭连接时，各平台报出来的错不一样。** 现在统一是 `io.EOF`，Windows 上也是。

除此之外，还从 go-rod 未合并的 PR 和 issue 里收割了 14 个修复，每个都配了回归测试：在快照上失败，在 wand 上通过。

- **Page / Element**：`WaitRepaint` 改在页面上下文里求值（rod #1241）、页面关闭时清掉自己的 session 状态（rod #1235）、元素截图按设备像素比裁剪（rod #1200）、`WaitLoad` 不再依赖 load 事件对象（rod #1150）、`WaitEnabled` 和 `WaitWritable` 各读各的属性（rod #1182）。
- **CDP**：控制帧不再进 JSON 解码器（rod #1187）、每次握手都用真实的 `Sec-WebSocket-Key`（rod #1228）。
- **Launcher / Input**：连接到已经在跑的浏览器（rod #1221）、`ResolveURL` 只认浏览器给的答复（rod #1176）、查找表里补上 FreeBSD（rod #1233、#828）、多字节字符算作一个按键（rod #1220）。
- **Hijack / Pool**：请求匹配按浏览器的规则来解析（rod #983）、`LoadResponse` 的 body 可以再发一次（rod #1128）、`Cleanup` 之后调用 `Pool.Get`（rod #1117）。

## 新增了什么

- **浏览器查找顺序。** `Launch` 用找到的第一个浏览器，一个都找不到才去下载：`Launcher.Bin()` → `-wand=bin=` → `WAND_BROWSER_BIN` → 系统里装的 Chrome / Chromium / Edge → wand 缓存里已有的 → 下载。本机装了 Chrome，就不会再下一份。
- **六个 `WAND_BROWSER_*` 环境变量**：`BIN`、`CACHE`、`HOSTS`、`DOWNLOAD`、`SOURCE`、`BINARY`，给那些改不了代码的部署用。go-rod 一个都没有。
- **`cmd/wand-fetch-browser`**：提前把浏览器下好并打印路径，适合 Docker 构建和离线打包。
- **浏览器和协议都有明确的 pin**：Target Chrome 153.0.8010.12、协议 r1680125、Companion Chromium 1680292，每个归档的哈希都记录在案。它们跟着 Chrome 稳定版里程碑一起动，由自动化的 Roll 更新，[`versions.json`](https://github.com/headlesslab/wand/blob/main/versions.json) 记录每个版本各带了哪三个 pin。
- **国产平台的构建路径**写进了 README：openEuler 24.03 LTS 用自带的 Go 就能编；低于 Go 下限 1.21 的发行版走交叉编译，或者从 golang.google.cn 装一份 tarball；`linux/loong64` 只指新世界（ABI 2.0）。

## 行为变化

有四处行为变了，而且编译器不会提醒你。

1. **User mode 换了自己的配置目录。** `NewUserMode()` 改用 `os.UserConfigDir()/wand/user-mode`。你原来 Chrome 里的登录态不会带过来；在这个目录里登录一次，之后就一直在。
2. **浏览器缓存目录换了**，改到 `os.UserCacheDir()/wand/browser`；而且只要机器上已经装了浏览器，就不会再去下载。原来的 `rod/browser` 目录既不读也不删，等你彻底不用 go-rod 了自己删掉即可。
3. **`Launcher.Leakless()` 现在控制的是 Orphan guard。** 名字、位置、默认值和保证都没变（`Launch()` 起的浏览器不会活得比你的进程久），只是这个保证改由操作系统和一条 wand 只开着、从不读写的管道来兜底，不再需要辅助进程。
4. **`cdp.ErrCtxDestroyed` 现在匹配两种错误文案。** 自己去比 `err.Message` 才会出问题，用 `errors.Is` 就好。

| ----------- | ------------------------------------------------------------------------------------------------ | ----------------------------------------------------- |

## 测试到什么程度

每个 PR、每次推送到 `main`，都会在四个平台上用真实的 Chrome 153.0.8010.12 带 `-race` 跑完整套件，其中两个 Linux 平台除 Go stable 外还会再跑一遍 Go 下限 1.21。每次跑完都会检查有没有残留的浏览器进程和配置目录。

- **Tier 1**：linux/amd64、linux/arm64、windows/amd64、darwin/arm64，在 CI 里用真实浏览器测。
- **Tier 2**：darwin/amd64、windows/arm64、linux/loong64，只构建和 vet，不用浏览器测。
- **支持窗口**：Chrome 150 到 153。Target Chrome 是被测的那一个；它之前的三个里程碑属于尽力而为，其中最老的那个每晚跑一次，但不阻塞发布。

运行时不做任何强制：主版本号对不上的浏览器照样启动，只会通过浏览器的 logger 打一行日志，把两个版本号都写出来。

## 后续计划

API modernization 和 Stealth 都在计划中，没有时间表，也不承诺先后顺序。

决定要不要用之前，有一点得先说清楚：**API modernization 会在之后某个 minor 版本改动 wand 的 API。** 1.0 之前的规则是 minor 可能破坏兼容、patch 一定不会，所以 `go get -u=patch` 是安全的升级方式；导出的符号在删除前，至少会带着写明替代者的 `// Deprecated:` 标记存活一个 minor（[ADR-0008](https://github.com/headlesslab/wand/blob/main/docs/adr/0008-fresh-v0-series-one-milestone-release-per-chrome-stable.md)）。wand 本身不含任何反检测代码，go-rod/stealth 也没法对着 wand 编译。

## 关于这个候选版本

`v0.1.0` 会原样沿用最后一个候选版本的代码，打标签的条件是：距 rc.1 满 14 天、距最新的候选版本满 7 天，并且没有标着 `release-blocking` 的 issue 还开着。中间只要有任何改动，就变成 rc.N+1。
