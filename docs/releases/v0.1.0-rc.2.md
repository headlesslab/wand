wand is a browser automation library for Go. It drives Chrome over the DevTools Protocol and needs no driver binary.

The code began as a snapshot of [go-rod](https://github.com/go-rod/rod) at commit `393ac0d` (2024-12-07), renamed to `github.com/headlesslab/wand` and maintained independently by headlesslab. Upstream's MIT licence and the attribution in [`NOTICE`](https://github.com/headlesslab/wand/blob/main/NOTICE) are kept as they are. Thanks to ysmood and to everyone who contributed to go-rod.

This is wand's first release, published as a release candidate. It redesigns no API. The work covers three areas: a dependency graph that upgrades cleanly, correct behaviour on current Chrome, and CI that proves both on every platform wand claims.

## What changed since rc.1

One fix, and it is a behaviour change: **`Navigate`, `NavigateBack` and `NavigateForward` return once the navigation has committed.** Chrome answers `Page.navigate` as soon as the navigation is ready to commit, which is before the renderer has committed the document, and a command bound for the renderer that is sent in that window can be lost with no answer at all, a hang that only the page's context ends ([#120](https://github.com/headlesslab/wand/issues/120)). The three calls now wait for the commit, which `Reload` already did. What they do not wait for is unchanged: the load event is still `WaitLoad`'s, so nothing that already waited waits twice.

## What this release fixes

As of today, go-rod has the following problems.

- **`go get -u` breaks the build.** Two upstream dependencies changed their APIs and the fixes are unmerged (rod #1203, #1195, #1202, #1237). wand's runtime graph is five modules headlesslab maintains — `eventbus`, `lazyjson`, `seqdiff`, `leakcheck`, `fetch` — plus `golang.org/x/sys`. No test framework is linked into your binary.
- **`launcher.NewUserMode()` fails on Chrome 136 and later** (rod #1189, #1184). Google's Chrome, as opposed to Chromium, refuses remote debugging on its default user data directory, which is the directory the preset used.
- **linux/arm64 has no browser to download.** The archive URL it falls back to no longer resolves. wand pins downloads to Chrome for Testing, verifies each against a recorded SHA-256, and probes Google's buckets and npmmirror concurrently, taking whichever answers first.
- **The guard binary is flagged by antivirus** (rod #865, #1214, #1232, #720, #1229). leakless writes a prebuilt executable to the temp directory; Windows Defender, 360 and Tencent PC Manager flag it, Falco alerts on it in Kubernetes, and its port lock can block indefinitely. wand writes no such file.
- **`errors.Is(err, cdp.ErrCtxDestroyed)` does not match on Chrome 152 and later.** Chrome changed the message returned when an evaluation is interrupted by navigation. wand matches both messages.
- **A connection closed by the browser reports differently per platform.** wand reports `io.EOF` on all of them, Windows included.

Fourteen further fixes are taken from go-rod's unmerged pull requests and its issue tracker. Each has a regression test that fails on the snapshot and passes here.

- **Page and element** — `WaitRepaint` evaluating under the page context (rod #1241), a closed page clearing its session states (rod #1235), element screenshots cropped by the device pixel ratio (rod #1200), `WaitLoad` without the load event object (rod #1150), `WaitEnabled` and `WaitWritable` reading their own attribute (rod #1182).
- **CDP** — control frames kept out of the JSON decoder (rod #1187), a real `Sec-WebSocket-Key` per handshake (rod #1228).
- **Launcher and input** — attaching to a browser already running (rod #1221), `ResolveURL` accepting only a browser's answer (rod #1176), FreeBSD in the discovery tables (rod #1233, #828), a multi-byte character counted as one key (rod #1220).
- **Hijack and pool** — request patterns parsed the way the browser parses them (rod #983), `LoadResponse` bodies that can be sent again (rod #1128), `Pool.Get` after `Cleanup` (rod #1117).

## What is new

- **Browser resolution.** `Launch` uses the first browser it finds and downloads one only when it finds none: `Launcher.Bin()`, then `-wand=bin=`, then `WAND_BROWSER_BIN`, then an installed Chrome, Chromium or Edge, then the browser already in wand's cache, then a download. A machine with Chrome installed triggers no download.
- **Six `WAND_BROWSER_*` variables** — `BIN`, `CACHE`, `HOSTS`, `DOWNLOAD`, `SOURCE`, `BINARY` — for deployments that cannot change the code. go-rod has none.
- **`cmd/wand-fetch-browser`** downloads the browser ahead of time and prints its path, for Docker builds and offline bundles.
- **Pinned browser and protocol.** Target Chrome 153.0.8010.12, protocol r1680125, Companion Chromium 1680292, with every archive hash recorded. The three move together once per Chrome stable milestone, through an automated Roll, and [`versions.json`](https://github.com/headlesslab/wand/blob/main/versions.json) records the pins each release carried.
- **Build paths for Domestic platforms**, documented in the README: openEuler 24.03 LTS builds with its packaged Go; distributions below the Go floor of 1.21 cross-compile or install a tarball from golang.google.cn; `linux/loong64` covers new-world (ABI 2.0) only.

## What changed in behaviour

Five behaviours changed, none of which produces a compile error.

1. **User mode uses a profile directory of its own.** `NewUserMode()` uses `os.UserConfigDir()/wand/user-mode`. Existing Chrome sign-ins do not carry over; a sign-in in that profile persists across runs.
2. **The browser cache moved** to `os.UserCacheDir()/wand/browser`, and an installed browser is used before any download. The old `rod/browser` directory is neither read nor deleted.
3. **`Launcher.Leakless()` switches the Orphan guard.** Its name, position, defaults and guarantee are unchanged — a browser `Launch()` started does not outlive the wand process — but the guarantee comes from the operating system and a pipe wand holds open without writing to it, rather than from a helper process.
4. **`cdp.ErrCtxDestroyed` matches two messages.** Comparing `err.Message` directly no longer works; use `errors.Is`.
5. **Navigations return once the document has committed.** `Navigate`, `NavigateBack` and `NavigateForward` return when the navigation they started has committed, rather than when Chrome answered `Page.navigate` or the history script ran. A call that used to return before the new document existed now returns after it does, so the command after it reaches that document; the load event is still `WaitLoad`'s.

## Migrating from go-rod

Five changes, each reported by the compiler or the flag parser.

| What             | From                                                                                                     | To                                                                  |
| ---------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| import prefix    | `github.com/go-rod/rod`, `rod.`                                                                          | `github.com/headlesslab/wand`, `wand.`                              |
| JSON helper      | `github.com/ysmood/gson`                                                                                 | `github.com/headlesslab/lazyjson`, identifier for identifier        |
| dev-only symbols | `lib/assets`, seven `lib/utils` helpers, the launcher's revision and host constants, `defaults.LockPort` | moved under `internal/`, or into `lib/launcher/pins`                |
| commands         | `lib/launcher/rod-manager`                                                                               | `cmd/wand-manager`, with the new `cmd/wand-fetch-browser` beside it |
| flag             | `-rod=`, `DISABLE_ROD_FLAG`                                                                              | `-wand=`, `DISABLE_WAND_FLAG`                                       |

[The migration guide](https://github.com/headlesslab/wand/blob/main/docs/migrating-from-go-rod.md) gives each one with the `sed` line that performs it, and a Known limitations section for what this release does not fix. Method names, receivers and behaviour are otherwise unchanged. That is a description of the current state, not a compatibility promise: wand offers no API compatibility contract with go-rod ([ADR-0002](https://github.com/headlesslab/wand/blob/main/docs/adr/0002-no-api-compatibility-with-go-rod.md)).

## What is tested

Every pull request and every push to `main` runs the whole suite with `-race` against Chrome 153.0.8010.12 on four platforms, the two Linux ones on the Go floor of 1.21 as well as on Go stable. Each run ends by checking that no browser process and no profile directory were left behind.

- **Tier 1** — linux/amd64, linux/arm64, windows/amd64, darwin/arm64: tested in CI with a real browser.
- **Tier 2** — darwin/amd64, windows/arm64, linux/loong64: built and vetted, never tested with a browser.
- **Support window** — Chrome 150 to 153. The Target Chrome is the tested one; the three milestones before it are best-effort, and the oldest of them runs nightly without gating anything.

Nothing is enforced at runtime: a browser of another major version is launched anyway, with one line through the browser's logger naming both versions.

## The container image

`ghcr.io/headlesslab/wand`, tagged with this release: `ubuntu:noble` with that same Chrome inside it, hash-verified at build time, `wand-manager` as its command, one manifest covering `linux/amd64` and `linux/arm64`.

## Verifying what you install

Every published manifest carries a build-provenance attestation and an SPDX bill of materials in Sigstore's public log:

```sh
gh attestation verify oci://ghcr.io/headlesslab/wand:<tag> -R headlesslab/wand
```

Tags are immutable and are never moved or deleted. The repository publishes an [OpenSSF Scorecard](https://scorecard.dev/viewer/?uri=github.com/headlesslab/wand), and [the security policy](https://github.com/headlesslab/wand/security/policy) states where a vulnerability report goes.

## Roadmap

API modernization and Stealth are planned. There are no dates and no commitment on order.

Note that **the API modernization will change wand's API in a later minor.** Until 1.0 a minor may break and a patch never does, so `go get -u=patch` is the safe upgrade, and an exported symbol carries a `// Deprecated:` marker naming its replacement for at least one minor before removal ([ADR-0008](https://github.com/headlesslab/wand/blob/main/docs/adr/0008-fresh-v0-series-one-milestone-release-per-chrome-stable.md)). wand contains no evasion code, and go-rod/stealth does not build against it.

## About this candidate

`v0.1.0` carries the last candidate's code unchanged. It is tagged once at least 14 days have passed since rc.1, at least 7 since the latest candidate, and no issue labelled `release-blocking` is open. Any change makes rc.N+1 instead.

Report problems in the [release candidate feedback issue](https://github.com/headlesslab/wand/issues/117), which is open for the whole soak, or in [a new issue](https://github.com/headlesslab/wand/issues/new). Include the Chrome version, the platform, and the behaviour under go-rod for comparison.

wand 是一个 Go 的浏览器自动化库，通过 DevTools Protocol 驱动 Chrome，不需要任何 driver 程序。

代码来自 [go-rod](https://github.com/go-rod/rod) 在 `393ac0d`（2024-12-07）这个提交的一份快照，重命名为 `github.com/headlesslab/wand`，由 headlesslab 独立维护。上游的 MIT 许可与 [`NOTICE`](https://github.com/headlesslab/wand/blob/main/NOTICE) 中的署名原样保留。感谢 ysmood，以及所有为 go-rod 贡献过代码的人。

这是 wand 的第一个版本，以候选版本发布，不包含任何 API 重新设计。改动集中在三个方面：依赖链可正常升级、在当前 Chrome 上行为正确、并在所有声称支持的平台上由 CI 验证前两项。

## rc.1 以来的变化

一个修复，同时是一处行为变化：**`Navigate`、`NavigateBack`、`NavigateForward` 现在等到导航提交后才返回。** Chrome 在导航 ready-to-commit 时就应答 `Page.navigate`，此时渲染器尚未提交文档；在这个窗口里发出的、发往渲染器的命令可能得不到任何应答，只能等页面的 context 结束（[#120](https://github.com/headlesslab/wand/issues/120)）。这三个调用现在等待提交，`Reload` 本来就是这么做的。不等待的部分没有变化：load 事件仍由 `WaitLoad` 负责，已经在等的代码不会等第二次。

## 修复了哪些问题

截至目前，go-rod 存在以下问题。

- **`go get -u` 会导致编译失败。** 上游两个依赖变更了 API，对应修复至今未合并（rod #1203、#1195、#1202、#1237）。wand 运行时仅依赖 headlesslab 维护的五个模块（`eventbus`、`lazyjson`、`seqdiff`、`leakcheck`、`fetch`）与 `golang.org/x/sys`，测试框架不会被链接进最终的二进制。
- **`launcher.NewUserMode()` 在 Chrome 136 及之后的版本上无法使用**（rod #1189、#1184）。Google 发行的 Chrome（区别于 Chromium）不允许在默认用户数据目录上启用远程调试，而该预设用的正是这个目录。
- **linux/arm64 无法获取浏览器。** 它回退使用的归档地址已失效。wand 将下载固定到 Chrome for Testing，逐个按记录在案的 SHA-256 校验，并对 Google bucket 与 npmmirror 并发探测，以最先响应者为准。
- **守护进程二进制会被杀毒软件拦截**（rod #865、#1214、#1232、#720、#1229）。leakless 会向临时目录写入一个预编译的可执行文件，Windows Defender、360、腾讯电脑管家均会报毒，Kubernetes 环境下 Falco 会告警，其端口锁还可能永久阻塞。wand 不写入此类文件。
- **Chrome 152 及之后 `errors.Is(err, cdp.ErrCtxDestroyed)` 不再匹配。** Chrome 变更了求值被导航打断时返回的错误文案，wand 对两种文案都匹配。
- **浏览器关闭连接时，各平台返回的错误不一致。** wand 在所有平台统一返回 `io.EOF`，Windows 同样如此。

另有 14 个修复取自 go-rod 未合并的 PR 与 issue，每个都配有回归测试：在快照上失败，在 wand 上通过。

- **Page / Element**：`WaitRepaint` 改在页面上下文中求值（rod #1241）、页面关闭时清除自身的 session 状态（rod #1235）、元素截图按设备像素比裁剪（rod #1200）、`WaitLoad` 不再依赖 load 事件对象（rod #1150）、`WaitEnabled` 与 `WaitWritable` 各自读取对应属性（rod #1182）。
- **CDP**：控制帧不再进入 JSON 解码器（rod #1187）、每次握手使用真实的 `Sec-WebSocket-Key`（rod #1228）。
- **Launcher / Input**：连接到已在运行的浏览器（rod #1221）、`ResolveURL` 只接受浏览器返回的地址（rod #1176）、查找表中补充 FreeBSD（rod #1233、#828）、多字节字符按一个按键处理（rod #1220）。
- **Hijack / Pool**：请求匹配按浏览器的规则解析（rod #983）、`LoadResponse` 的 body 可再次发送（rod #1128）、`Cleanup` 之后调用 `Pool.Get`（rod #1117）。

## 新增了什么

- **浏览器查找顺序。** `Launch` 使用找到的第一个浏览器，全部未命中才下载：`Launcher.Bin()` → `-wand=bin=` → `WAND_BROWSER_BIN` → 系统已安装的 Chrome / Chromium / Edge → wand 缓存中已有的 → 下载。已安装 Chrome 的机器不会触发下载。
- **六个 `WAND_BROWSER_*` 环境变量**：`BIN`、`CACHE`、`HOSTS`、`DOWNLOAD`、`SOURCE`、`BINARY`，用于无法修改代码的部署环境。go-rod 没有对应机制。
- **`cmd/wand-fetch-browser`**：提前下载浏览器并输出其路径，用于 Docker 构建与离线打包。
- **浏览器与协议的 pin**：Target Chrome 153.0.8010.12、协议 r1680125、Companion Chromium 1680292，每个归档的哈希均记录在案。三者随 Chrome 稳定版里程碑一同更新，由自动化的 Roll 提交；[`versions.json`](https://github.com/headlesslab/wand/blob/main/versions.json) 记录每个版本所带的 pin。
- **国产平台的构建路径**（见 README）：openEuler 24.03 LTS 使用自带的 Go 构建；低于 Go 下限 1.21 的发行版采用交叉编译，或从 golang.google.cn 安装 tarball；`linux/loong64` 仅指新世界（ABI 2.0）。

## 行为变化

以下五项行为发生了变化，且都不会产生编译错误。

1. **User mode 使用独立的配置目录。** `NewUserMode()` 改用 `os.UserConfigDir()/wand/user-mode`。原有的 Chrome 登录态不会迁移过来；在该目录中登录后，登录态在后续运行中保留。
2. **浏览器缓存目录变更**为 `os.UserCacheDir()/wand/browser`，且已安装的浏览器优先于任何下载。原 `rod/browser` 目录不读取也不删除。
3. **`Launcher.Leakless()` 现在控制的是 Orphan guard。** 名称、位置、默认值与保证均不变（`Launch()` 启动的浏览器不会比 wand 进程存活更久），但该保证由操作系统和一条 wand 只持有、不写入的管道提供，不再依赖辅助进程。
4. **`cdp.ErrCtxDestroyed` 匹配两种错误文案。** 直接比较 `err.Message` 不再可行，请改用 `errors.Is`。
5. **导航调用等到文档提交后才返回。** `Navigate`、`NavigateBack`、`NavigateForward` 在自己发起的导航提交之后返回，而不是在 Chrome 应答 `Page.navigate` 或历史脚本执行完时返回。原先可能在新文档出现之前就返回的调用，现在返回时新文档已经就位，紧随其后的命令能到达该文档；load 事件仍由 `WaitLoad` 负责。

## 测试范围

每个 PR 与每次推送到 `main`，都会在四个平台上使用真实的 Chrome 153.0.8010.12 带 `-race` 运行完整测试套件；其中两个 Linux 平台除 Go stable 外，还会在 Go 下限 1.21 上再运行一次。每次运行结束都会检查是否有残留的浏览器进程与配置目录。

- **Tier 1**：linux/amd64、linux/arm64、windows/amd64、darwin/arm64，在 CI 中使用真实浏览器测试。
- **Tier 2**：darwin/amd64、windows/arm64、linux/loong64，仅构建与 vet，不使用浏览器测试。
- **支持窗口**：Chrome 150 至 153。Target Chrome 为受测版本；其之前的三个里程碑为尽力而为，其中最旧的一个每晚运行一次，且不阻塞发布。

运行时不作强制：主版本号不匹配的浏览器仍会启动，仅通过浏览器的 logger 输出一行日志，写明两个版本号。
